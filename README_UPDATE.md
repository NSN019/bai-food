# BAI FOOD — локальное обновление

## Последнее обновление

- Для Kaspi-оплаты после успешного сохранения заказа открывается официальная ссылка Kaspi Pay; WhatsApp больше не используется.
- В навигации оставлены «Акции», «Сеты» и «Фастфуд»; раздел «Курица» переименован в `CHICKEN`.
- Удалены Pizza Time, Super Combo, большой/маленький фри и четыре пиццы; у пиццы отключены добавки.
- Для новых заказов оставлены зоны Бақтыбай, Елтай, Өтенай и Балпық би.
- Акция Ayran теперь рассчитывается за каждые полные четыре отдельно выбранных донера.
- При наличной оплате добавлен выбор «Без сдачи» или сумма, с которой нужна сдача.
- При принятии заказа кассир обязательно выбирает 20/30/40 минут.
- Клиентский экран подтверждения проверяет принятие и показывает примерное время.
- Добавлены локальные промо-изображения Pepperoni и донер + Ayran.
- Звук кассы заменён на короткий оригинальный bell/chime с повтором каждые 3 секунды.
- Новый непринятый заказ можно безопасно отклонить с причиной, не удаляя историю.
- Добавлены 8 суши-сетов и 21 позиция суши с локальными WebP-фотографиями.
- В категориях появились «Суши сеты» и «Суши»; суши расположены перед напитками.
- Лишняя кнопка «Акции» рядом с «Смотреть меню» удалена.
- Все 64 карточки меню приведены к единому формату 1200×900: продукты увеличены,
  соусы и банки напитков получили отдельные изображения, а фастфуд- и суши-сеты
  собраны в крупные композиции для корректного отображения на телефоне.
- Часть фотографий временно взята из открытых интернет-источников. После фирменной
  фотосъёмки их можно заменить без изменения логики сайта и базы данных.

Для уже установленной полной миграции и предыдущего patch используйте только новый patch:

`supabase_patch_menu_prep_change.sql`

Patch не удаляет и не изменяет старые заказы, не меняет RLS и сохраняет старую
`create_order`. Предыдущие SQL-файлы повторно запускать вместо нового patch не нужно.

Новые поля `orders`: `prep_minutes`, `cash_change_mode`, `cash_change_from`,
`cancelled_at`, `cancellation_reason`, `cancellation_comment`.

Версия подготовлена поверх текущей структуры проекта. Git push и публикация не выполнялись.

## Порядок применения

1. Сделать резервную копию текущего проекта и базы Supabase.
2. В Supabase SQL Editor сначала выполнить `supabase_patch_menu_prep_change.sql`, затем `supabase_patch_sushi_menu.sql`.
3. Локально заменить `index.html`, `style.css`, `script.js`, `admin.html`, `admin.css`, `admin.js` и добавить папку `assets`.
4. Проверить клиентский заказ и кассу через Live Server.
5. Только после подтверждения владельца выполнить git push/deployment.

Новый клиент сначала вызывает `create_order_v2`. Если миграция ещё не применена, он безопасно откатывается к существующему `create_order`, поэтому текущий RPC не удаляется и не заменяется.

## Проверка

```bash
node --check script.js
node --check admin.js
node test_business_rules.cjs
```

Автоматический набор содержит 69 проверок, включая Kaspi Pay только после
успешного сохранения, очистку устаревшей корзины, приём/отклонение заказов,
звук, безопасный клиентский статус и совместимость старых заказов.
